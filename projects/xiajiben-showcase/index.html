Features

不是又一个记账本，是一个“看得见”的库存

核心问题只有一个：东西放哪了、还能放多久、是不是该处理了。所有设计都围绕它展开。

🗂️

位置 · 分类 · 状态 三个视角

内置冰鲜区、药品区、常温区三大位置，每个位置下的二级分类（冷藏 / 微冻 / 冷冻 / OTC / 零食 / 粮油 …）可自行重命名、增删。首页一键切换视角。

状态由云函数按保质期现场推算，不落库，永远准确。
📸

拍照识别包装

拍一张包装照，视觉大模型直接抽取名称、数量、保质期与品类。包装上没写保质期时，给出带来源标注的“AI 建议赏味期”，不假装它是真实保质期。

云函数 xiaji-vision · 通义千问 VL
🧾

小票批量录入

买菜回来拍一张小票，一次识别出多件物品和价格，逐条确认后批量写入，同时生成购买记录，月底还能看花费。

购买记账可在设置里一键关闭。
⏰

临期提醒：系统日历 + 打开拦截

个人主体做不了长期订阅消息，就换思路：把临期日写进手机系统日历；每次打开小程序，有临期或过期就先弹拦截层，处理完才放行。

频率可选：每天一次 / 每次打开。
✋

看板长按批量操作

长按缩略图进入抖动选择模式，左上角圆圈勾选，底栏一键消耗、清理或删除记录。处理一批临期物品，三秒完成。

后端提供 batchConsume / batchDiscard / batchDelete。
🔐

隐私与合规做到位

识别后原图立即从云存储删除；账号注销一键硬删除全部数据与文件；反馈内容过微信内容安全；未登录也能先体验，不强制授权。

登录采用 chooseAvatar + 昵称输入的新规写法。

Decisions

几个改变项目走向的取舍

做独立项目，比“做了什么”更值得讲的是“为什么不做什么”。

自建 NestJS + MySQL + Redis→腾讯云云开发

放弃服务器，反而更快上线

最早已经搭好 NestJS 脚手架，后来发现产品只有 CRUD 加偶尔识别，不值得养一台机器。改用云函数 + 文档库后，不买服务器、不备案域名，身份由 OPENID 直接给，鉴权代码直接消失。旧脚手架冻结留作对照。

web-view 套壳 H5→uni-app 原生化

一步到位，不走“先套壳再重写”

web-view 承载核心业务是审核高频被拒点。既然目标是正式上线，“要不要做”已经决策完毕，中间再绕一圈只会白做。H5 版本保留，但定位为独立演示线。

订阅消息推送→系统日历 + 打开拦截

在平台限制里找真正可用的方案

个人主体拿不到长期订阅，一次性订阅体验又差。换成把临期日写入手机日历，加上打开即拦截。真机验收发现 iOS 跳转页无法勾选响铃，这是平台限制，v1 接受差异，不硬补。

条码扫码录入→手填 / 拍照 / 小票

敢下线自己做过的功能

条码查询依赖第三方商品库，覆盖率与成本都不可控，查不到时体验比手填更糟。验证后果断下线，前端解码库、云函数 action 和集合一并清理，录入收敛到三条稳定路径。
